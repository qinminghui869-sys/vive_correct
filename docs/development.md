# 开发说明

## 数据流与模块

主路径是选帧、可选 AI 预审、人工审核、版本化依据包，然后是共用修正 Parquet、RRD 或显式覆盖。同一位姿变换只实现一次。

- `run_dataset.py`：命令调度。`data/`：目录规则、样本发现和源文件。`cv/`：选帧与发布。
- `ai/`：最终结果复核和单图输入，建议独立保存。
- `estimate/`、`batch/`：检测、几何、候选选择、模型复核与交付。
- `review/`：人工记录、轴向计算、依据包、页面和重建入口。
- `runtime/`：跨进程任务锁与进程内缓存。
- `export/`、`ego_data/`：录制编排、同步和渲染；旧版深度元数据由 `depth_metadata.py` 解析，RRD 格式兼容与模式选择由 `render_inputs.py` 管理，RGB 手点投影由 `rgb_projection.py` 管理。

计算公式见 [校准模型](hand_pipeline.md)，API 与 schema 见 [字段与接口](observations_schema.md)。检测与模型默认参数维护在 `vive_correct/config/*.yaml`；审核并发与缓存默认值维护在 `review/review_server.py`。显式 CLI 参数优先。

## 必须保持的约束

### 发布与并发

- 同一输出目录只有一个选帧写入进程。先保存图片、候选池，再原子发布 `features.json`；已进入人工审核的结果不可自动覆盖。
- 数据编号持久化且只追加。浏览器每秒轮询轻量状态，列表版本变化时更新列表；新增结果不覆盖当前草稿。
- 审核与导出队列独立，排队即取得跨进程单条任务锁。中断任务仅恢复状态，不自动重提；版本冲突必须拒绝。
- 审核服务的原帧、PNG、深度帧及掩码、相机和姿态共用有界 LRU（`--cache-mib` 可调），键绑定文件身份、大小及高精度时间戳。相同键的并发缺失合并计算，失败后可重试，大数组复制在锁外完成。
- 预览与图像编码分别限流，缓存命中不占计算槽位。角度变化复用几何；四角、帧、源数据或外参变化使几何缓存失效。前端取消旧预览并校验数据、手侧、帧号及编辑版本。
- 静态汇总页最多每秒刷新，结束时强制刷新。记录扫描、任务排队与执行、文件修正、RRD 渲染耗时；性能对比使用同一输入和参数，不降低检测或录制质量。

并发参数与默认值统一见 [操作指南](review_rebuild.md#concurrency)。

### AI 与人工边界

- AI 预审的调用上限、粗区域与旋转约束统一见 [处理边界](ai_review.md#review-scope)；新增逻辑不能改变原有身份判断接口。四角和姿态由共享几何逻辑计算。
- AI 建议绑定输入、代码和标定；失效建议不能静默应用。人工编辑与已通过记录不能被后台结果覆盖。
- 回归需覆盖局部检测失败、轴旋转顺序与奇异位置、调用上限、失效绑定和人工审核限制。

### 校验与写入

- 打开数据、通过审核、导出和重建执行必要的完整校验，缓存不能替代依据校验。输入、审核、标定或计算代码变化使旧依据失效。
- 整条排除以输出根目录的 `rejected_episodes.json` 为准，服务端保存、通过、导出和重建必须执行拦截；记录按样本路径去重，写入持有单条任务锁及根索引锁。缺失图像或几何不能阻止拒绝操作。
- 预览只读；审核重新计算，不信任客户端投影。缺失姿态不使用单位旋转代替。
- 审核和导出只写输出目录。源数据写入入口为 `rebuild --in-place` 和 [深度原点写回脚本](review_rebuild.md#depth-origin-writeback)，共用六文件事务接口。
- 长操作持有单条输出锁，根锁只用于索引更新。读源数据用共享锁，覆盖和恢复用排他锁；同时需要两类锁时，先取输出锁，再取源锁。
- 六文件先生成、校验，再登记基线、替换、校验和提交。失败或中断恢复到本次执行前。`meta/` 与源文件在同一事务。
- JSON 不允许 NaN。事务登记需同步文件和目录。
- RRD 导出范围和覆盖校验必须使用实际渲染模式的时间线，见 [RRD 输入](../ego_data/README_rerun.md#rrd-inputs)。RGB 回退读取已修正文件，不重复施加校准；所有二维原点计算共用 `depth_origin.py`，保存的校准通过 `require_depth_alignment` 校验，不允许 PnP 深度回退；缺掩码必须保留预览标记。

## 检查与验证

需要 Python 3.10+、Node.js 和开发依赖：

```bash
python3 -m pip install -r requirements-dev.txt
bash scripts/check.sh
```

脚本执行文档链接检查、Ruff、前端语法检查及两组单元测试，CI 使用同一入口；无需真实数据或模型密钥，HTTP 测试需允许绑定本机临时端口。修改 Python 后格式化相应文件；前端格式使用 Prettier 3.6.2：

```bash
python3 -m ruff format path/to/changed.py
npx --yes prettier@3.6.2 --write vive_correct/review/review_ui
```

新增测试应覆盖可观察行为：不同参考帧与同步边界、旋转与骨长、字段保真、动态发布、独立队列、缓存失效、版本冲突、重复重建及失败恢复。涉及交互时补充浏览器“调整—暂存—重载—审核—手动导出”验证；记录样本、参数、输入与代码版本，区分功能通过和精度验收。

## 文档维护

- README 只保留上手步骤和导航；操作、接口、实现约束分别维护，交叉引用代替重复说明。
- 文件链接使用仓库内相对路径，目标必须纳入 Git；本地配置、生成产物和机器路径用代码文本，不做文件链接。
- 章节链接使用显式、稳定的英文锚点，例如 `<a name="rebuild-and-backup"></a>` 对应 `#rebuild-and-backup`。修改标题时保留锚点；不要改成 `id`，GitHub 会重写它，导致片段链接无法定位。
- 命令注明执行目录，使用 `/path/to/dataset` 表示待替换路径；覆盖源数据的命令单独列出。
- 参数以配置和 CLI 为准；测试记录标明日期、版本、样本及未通过项，不将历史实验当作当前精度承诺。

单独检查文档运行 `python3 scripts/check_docs.py`。检查覆盖 Git 跟踪的 Markdown、相对文件链接和显式锚点，不访问外部网站或本机审核服务。
